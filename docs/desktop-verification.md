# FrameAtlas verification — 2026-11-01

This record describes checks actually run on the local Windows x64 build. It is not a retrieval-accuracy benchmark or a claim of validation on a large video collection.

## Application behavior

- Python 3.14.10 runtime: **13 backend tests passed**, including library persistence, duplicate imports, missing/corrupt sources, cancellation, restart checkpoints, changes to sources/settings, authorization, CORS, byte-range playback, saved intervals and accurate export without overwrite.
- A regression test reproduced a final-batch pause incorrectly marking an incomplete video ready. Completion now depends on committed frame counts. Resuming indexes the remaining frames.
- Temporal checks cover the missing nth event and ranking across 100 videos, including a best match at the end of the collection. The original audit also passes.
- **4 Playwright workflows passed** against the production frontend and real HTTP/media service. They cover text/image search, actual video decoding, save/reload/remove, library filtering, settings, keyboard controls, a 920 px window, browser-panel import/export and an automated WCAG AA check. Their embeddings are deterministic fixtures; they do not establish EG2 accuracy.
- TypeScript/production frontend build and `cargo check --release` passed. The production npm dependency audit reported zero known vulnerabilities at the time of the check.

Evidence is under ignored `outputs/onboarding/`: `desktop-tests-314.log`, `desktop-ui-tests.log`, `temporal-final.log`, `pause-final-before.log`, `rust-check.log`, `frontend-build-final.log`, and `npm-audit.json`.

## Actual EG2 acceptance

Model: `google/embeddinggemma-2`, revision `f9972ac22e696a105c482202646979e33e4b5a1e`, text and vision only. CPU FP32, 768-dimensional normalized embeddings, 140 vision tokens, 0.5 sampled frames/second. Hardware: Intel i7-11800H, 16 GB RAM. The installer runtime contains CPU PyTorch.

Inputs were one [MDN CC0 flower video](https://interactive-examples.mdn.mozilla.net/media/cc0-videos/flower.mp4) and two generated geometric videos: **3 videos, 9.005 seconds, 5 indexed frames**. English and Vietnamese flower queries ranked the flower video first; the red-square query ranked the red video first. A real frame query also ranked the flower video first. A saved interval survived reopening the database. Its exported MP4 decoded and measured 2.002 seconds for a requested 2-second interval.

A separate clean-library run with `HF_HUB_OFFLINE=1` and `TRANSFORMERS_OFFLINE=1` passed using locally available model files and bundled FFmpeg 9.0.2:

| Operation | Observed time |
| --- | ---: |
| Index 5 frames, including model load | 32.25 s |
| English text query, model loaded | 84 ms |
| Vietnamese text query, model loaded | 84 ms |
| Red-square text query, model loaded | 96 ms |
| Image query, model loaded | 1,724 ms |

These are individual observations, not percentiles or throughput promises. In the live Codex panel, the first text search took about 42 seconds including cold initialization while other build tasks were running. Subsequent queries reuse the loaded model. CPU indexing is not real-time on this laptop.

The first run from the copied package runtime recorded a **134.8-second cold text search** while a Rust release build was running. That run still passed text/image retrieval, authenticated HTTP, range playback and 2.002-second clip export. The concurrent build and cold runtime paths make that observation unsuitable for comparison with the warm timings above. Cold-start latency remains a product limitation on this CPU configuration.

Evidence: `desktop-real-acceptance.json`, `desktop-offline-acceptance.json`, their logs, `flower-query.png`, and the timestamped `flower-export-*.mp4` files. Run `scripts/accept_desktop_real.py --data-dir <isolated-library> --report <report.json>` to avoid writing to a currently open library.

The acceptance scripts expect `data/models/embeddinggemma-2`, `data/acceptance-media/flower.mp4`, and the synthetic videos generated by the recorded onboarding smoke run under `data/smoke-9lxwfmyv/videos`. They are deliberately excluded from Git and the installer.

## Packaging and UI boundaries

The first native Windows build was launched successfully and showed its local library. Subsequent checks use the Codex right-side browser and hidden processes, as requested by the user. Native file-dialog/export selection was not completed interactively; the browser path-selection flow and backend export were verified.

The final installer build log is `desktop-build-final.log`. Package verification and hashes are recorded alongside it after bundling. An unsigned local build is not a signed public release. Other operating systems, GPU packages, huge libraries, retrieval accuracy on a representative dataset and audio/OCR features have not been validated or implemented.

The interface concept and design critique are in [the visual lab](lab/README.md). Generated mockup content is separate from real application data.
